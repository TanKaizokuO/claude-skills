---

Read-only weekly review of LLM spend. Never edit configs, databases or jobs from this skill; changes are proposed to the user, not applied.

1. Sync omp's stats: `omp stats -s` (the db is lazily synced, so it is stale otherwise).
2. Run `python3 ~/.claude/skills/llm-cost-audit/scripts/audit.py [--days 7] [--tz <zone>] [--min-cost 100] [--json]`. It works on a temp copy of `~/.omp/stats.db`, reads `~/.claude/projects/**/*.jsonl` (deduped on message id + requestId), and computes cost from raw tokens using canonical `pricing.json` via tokentrack (stored costs are unreliable). Days are calendar days in the effective timezone (default: canonical system zone, e.g. `Asia/Kolkata`), today included. Models missing from canonical `pricing.json` are listed as unpriced, not guessed. Every text run (not `--json`) also saves its report to `~/.local/share/llm-cost-audit/latest.txt`, overwriting the previous one; other skills read that file instead of re-running the audit.
3. Summarise for the user, conclusions first: totals per tool, model, project and day; top sessions; spikes; then each "Needs review" detector (flags for review, not proof of waste: repeated sleep-call loops at high context, cache reads above 100k context, premium models on read-only subagents, old-model use after the newer one shipped).
4. Walk the TRIAGE table with the user (sessions at or above the threshold with zero edit/write calls). They decide research vs waste; do not label them yourself. Prompt snippets are redacted when they look secret-like. Never print more of a user prompt than the table shows; if a plaintext secret turns up, tell the user to rotate it without repeating it.
5. Agree actions with the user (model routing, compaction, stopping loops). Update canonical `pricing.json` and the `SUPERSESSIONS` list in `audit.py` when new models, rates, or versions appear.
6. After the summary and triage, write the Token Ledger's Audit tab and refresh its data in one publish. Invoke the `token-ledger-update` skill with the Skill tool and args `audit-tab`, and do these two things before its republish step:
   - Run `audit.py` with the same `--days`/`--tz`/`--min-cost` plus `--json` and save the output to `$SCRATCH/audit.json`. Write `$SCRATCH/audit-notes.json` with this week's judgement text: `findings` (extra `[label, text]` rows, such as open questions or changes applied since the last audit), `suggestions` (`[title, text]` proposals agreed or still pending from step 5) and `verdicts` (`{"MM-DD|inr": "research"|"waste"}`, only for the ones the user gave in step 4; leave the rest out).
   - Run `python3 -I ~/.claude/skills/llm-cost-audit/scripts/render_audit_tab.py <merged.html> $SCRATCH/audit.json $SCRATCH/audit-notes.json <merged.html>` on the merged file. It rewrites only the `<!-- Audit View -->` block (numbers, triage table, detector rows, unpriced models) and leaves the UI and `DATA` alone. Then publish.
   Run it once per audit, after the audit is complete. `token-ledger-update` never runs this audit, so there is no loop. Do not print the report again here; step 3 already summarised it.

Rules: money is INR at canonical `pricing.json` rate (95.56/USD) and is API-equivalent value, not necessarily cash on a subscription. "Avoidable" old-model spend counts only requests made after the newer model was available. Days are calendar days in the effective timezone (`--tz`, default: canonical system zone). `--days 9999` covers everything. The audit itself is read-only; the one exception is step 6, which republishes the Token Ledger artifact (data plus Audit tab) through `token-ledger-update`.
